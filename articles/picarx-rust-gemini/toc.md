# Qiita記事構成案: RustとGemini構造化出力によるラズパイカー(PiCar-X)の型安全な制御

## 読者ターゲット
- **主要ターゲット**: Rustで実世界のIoT/ロボット（PiCar-X）を動かしたい開発者
- **課題意識を持つ人**: LLMからJSONを取得する際に出力のブレやパースエラーに悩んでいる人
- **技術的関心**: Gemini APIの「Structured Outputs (構造化出力)」の実践的な使い方と、Rustの強力な型システムとの親和性を知りたい人

## 構成案 (目次)

### 1. 導入 (Introduction)
- 本記事のテーマ：不確実なLLMと、絶対的な安全性が求められるロボットを「Rust × Gemini」でどう繋ぐか
- ラズパイカー「PiCar-X」の紹介と、自然言語（日本語/英語）で走行制御するシステムの概要
- 【導入部で軽く解説】本プロジェクトでRust言語を採用するメリット（安全性、非ブロッキング並列処理の容易さ）

### 2. 課題：構造化出力がない場合の制御破綻
- **自然言語指示の不確実性**: 「JSONで返して」というプロンプト指示だけでは、マークダウン装飾が混入したり、余計な説明文が入ったりする
- **ネストされたJSONのキー名ゆらぎ**: 
  - 本プロジェクトの核心である「センサー値による自律制御（until条件）」のような、複雑でネストされたJSON構造では、LLMがキー名を間違える（例: `sensor` を `sensor_kind` にする等）
- **物理デバイスにおけるパースエラーの深刻さ**:
  - Webアプリケーションと異なり、ロボット制御における1文字のエラーは「制御停止」や「暴走」に繋がり、ハードウェア破損などの物理的な被害を生むリスクがある

### 3. 解決策：Gemini API の Structured Outputs (構造化出力)
- **Structured Outputsとは**: APIリクエスト時に `responseSchema` を送信し、モデルのレスポンスが100%そのスキーマに適合することを保証する機能
- **型安全なデシリアライズ**: 保証されたスキーマにより、Rustの `serde_json` で安全にデシリアライズでき、パースエラーによるランタイムパニックを極限まで低減できる

### 4. 実装詳細：`gemini_agent.rs` の詳細解説
- **APIリクエストの構造**:
  - `generationConfig` における `"responseMimeType": "application/json"` と `"responseSchema"` の指定方法
- **JSON Schemaの定義**:
  - Rustコード内で定義する `response_schema`（オブジェクト、配列、列挙型 enum のスキーマ設計）
- **Rustの型定義とのマッピング**:
  - JSON Schemaと、Rustの [command.rs](file:///c:/Users/tacta/Dev/PiCarX/rust/src/llm_agent/command.rs) に定義された `Command` enum（`serde(tag = "action")`）の対応関係
- **非同期通信スレッド**:
  - `GeminiAgent::new` 内で `thread::spawn` を行い、HTTP通信（`ureq`）をメインループ（カメラ映像描画等）から分離し、ノンブロッキングで処理するアーキテクチャ

### 5. 高度な工夫：until条件による安全な自律制御
- **時間の経過だけではない制御**: 単に「3秒前進」だけでなく、「超音波距離センサーが15cm未満になるまで前進」という、センサー値と連動した自律停止制御
- **Rust側でのステートマシン実行**:
  - 複雑な論理演算（AND/OR/NOT）を含む `until` 条件（`ConditionExpr`）をRust側の `CommandQueue::tick` で非ブロッキング評価するロジックの美しさ

- 構造化出力によって、AIの「あいまいさ」を「確実な型」に閉じ込め、Rustで安全に実世界を動かすアプローチの総括

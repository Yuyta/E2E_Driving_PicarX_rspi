はじめに

PiCar-X の開発で使う画面は、次の2種類です。

  • Control Center（この画面、ブラウザ）: モデルとデータの管理、ツールの起動、ジョブの記録。まずここを開きます。
  • Qt の画面（デスクトップのウィンドウ）: 会話・手動操作、走行データ収集、データ確認・ラベル。カメラやパッド、マイクを使う作業です。Control Center の「ツール」から開きます。

起動と終了

やること方法
Control Center を開くcd python の後に uv run python -m src.gui.web。ブラウザが自動で開きます（http://127.0.0.1:8765/）
ランチャー（Qt）から開くuv run python -m src.gui.launcher を起動し、右上の「Control Center を開く（ブラウザ）」
終了する起動したターミナルで Ctrl+C。ランチャーから開いた場合は、ランチャーを閉じると終わります
サーバーを止めると、開いている画面は使えません。「サーバーに接続できません」と出たら、もう一度起動してからページを開き直してください。右上に「サーバー停止中」と出ている時も同じです。

安全のきまり

  • 画面右上の ■ 緊急停止 は、どの画面からでも押せます。Pi に緊急停止を送り、動いている走行のジョブも止めます。解除するまで、Pi は走行を受け付けません。
  • 車体が動く の付いたツールは、安全の確認にチェックを入れないと起動できません。周りに人・物・段差がないこと、すぐ緊急停止できることを確かめてから起動します。
  • 車体が動くジョブを止める時は、ジョブの画面の「■ 車体を止めて終了」を使います。Pi に停止を送ってから PC のプロセスを止めます。Pi の自律走行は、PC のプロセスを止めても続くためです。

いつもの開発の流れ

  1. 集める: 走行データ収集か自動データ収集。1回 150 秒ほどで、セッションが data/raw/<日時> にできます。
  2. 確かめる: セッションの報告で記録の質を確かめ、データ確認・ラベルでおかしいフレームを除外します。
  3. 封をする: マニフェスト作成（引数 --data_dir data/raw）。後から変わっていないかを確かめられるようになります。
  4. 学習する: モデル学習。出力先は次の版（models/v007 など）を自動で入れます。
  5. 評価する: 交差検証をして、今の設定の結果と比較します。
  6. 決める: モデル詳細の「採否を変える」で 有効 か 却下 にします。理由も書きます（履歴に残ります）。
  7. 配置する: モデル詳細の「Pi へ配置…」。
  8. 走らせる: Pi 自律走行。
  9. 振り返る: 走行記録の取り込みをして、走行記録で人の介入の回数を比べます。介入が多い場面のデータを集めて、1 に戻ります。

Control Center の画面

概要

全体の状態を1枚で見ます。最初に「モデルの状態」の4つを確かめます。

項目意味
Pi で使用中（配置の記録）Control Center か src.e2e.deploy.pi で最後に使用中にした版。記録の外で Pi を操作すると合わなくなります
Pi の最後の走行で使った版取り込んだ走行の記録（data/runs）のうち、最後の走行の版。上と違う時は「Pi のモデル一覧」で確かめます
最新のモデル作った時刻が一番新しい版
最新の有効なモデル「有効」にしてあり、来歴の確認に誤りがない版のうち、一番新しいもの。走らせるならこれです

「確認すること」には、来歴の誤り、採否を決めていないモデル、ラベルのないセッションなどが出ます。押すとその画面へ移ります。

モデル

学習したモデルの一覧です。上のボタンで採否ごとに絞れます。行を押すと詳細を開きます。

採否使う場面
候補学習しただけで、まだ判断していない（作った直後はこれ）
有効走行に使ってよいと判断した。理由が必要です
却下使わない（性能や来歴に問題がある）。理由が必要です
廃止以前は使っていたが、新しい版に替えた

採否は models/registry.json に、前後の採否・時刻・理由付きで残ります。「来歴の確認」が 要対応 のモデルは、「有効」にしても有効なモデルとして扱いません。

モデル詳細のタブ:

  • 概要: 確認の結果（ONNX があるか、どのコミットで学習したか、データが学習時のままか）、要点、採否の履歴
  • 来歴: どのセッションを学習・検証に使ったか、今のデータが学習時と同じか、コマンド・コード・パラメーター・ハッシュ
  • 学習: 損失の推移（線をなぞると値が出ます）と、保存した最良のエポック
  • 評価: 向き別・意図別の誤差、同じデータの交差検証と、基準（常に直進、意図の平均）との比較
  • 走行・配置: Pi での走行の回数と介入、配置の履歴
  • 環境: 学習に使ったソフトの版と前処理の値

上のボタン: 「データを検証」は、学習に使ったセッションの全ファイルのハッシュを確かめ直します（数秒かかります）。「バンドル作成」「Pi へ配置…」は、そのモデルを入れた状態でツールを開きます。

比較・評価

上で選んだモデル（3つまでが見やすい）の値とパラメーターを並べます。違うパラメーターには「違い」の印が、一番よい値には ◀ が付きます。下には交差検証の結果と、交差検証の比較の判定（採用してよい / 今の設定のまま / 比べられない）が出ます。偏りのない比較には、モデルの検証の値ではなく、交差検証の結果を使います。

データ

セッションごとのフレーム数、時間、舵角の分布（左・直進・右）、マニフェスト、手作業のラベル、使ったモデルです。行を押すと、等間隔に抜き出した画像が見られます。ラベル（labels.jsonl）のないセッションは記録が途中で止まったもので、学習には使われません。

来歴

走行データ → 手作業のラベル → モデル → 交差検証・Pi での走行 のつながりの図です。節を押すと、その元になったものと、そこから作られたものを強調します。実線は学習に使用、破線は検証に使用、点線は同じデータで評価、を表します。

走行記録

Pi の自律走行の記録です。モデルごとに、10分あたりの人の介入の回数を比べます（少ないほどよい）。記録は「走行記録の取り込み」で Pi から持ってきます。

ツール・ジョブ

「ツール」でツールを起動すると、「ジョブ」に出力と結果が残ります（data/jobs）。ジョブの画面では、出力がそのまま流れ、「同じ引数でもう一度…」で再実行できます。学習のジョブは、作ったモデルの「来歴」タブからたどれます。

起動の画面の「実行引数」は、ターミナルでの python -m <モジュール> の後ろと同じ書き方です。「操作の例」から選ぶと、よく使う引数が入ります。models/vNNN を含むツールでは、「モデル」から版を選べます。

各画面（Qt）の使い方

会話・手動操作

使う場面: Pi と会話する、カメラを見る、手で少しだけ動かす、車体の状態を確かめる。

場所使い方
上の帯安全の状態（安全 / 注意: 障害物が近い / 緊急停止中）と緊急停止のボタン
AI のモデル会話に使う LLM を選びます。既定は設定の値です
カメラ1秒ごとに更新します。「今の画像を取得」ですぐ取り直します。最小化している間は取りに行きません
センサー前方の距離（2秒ごと）と床センサーの値
手動操作▲▼ で 0.4 秒だけ前進・後退（速さ 30）、◀ ▶ で舵を左右へ、● で中央へ。「床を校正」は、車体を床に置いた状態で段差の基準を測ります
会話文字を入れて Enter か「送信」。「🎤 押して話す」は押している間だけ PC のマイクで録音し、離すと送ります（音声の追加パッケージが必要）

引数: なし。

走行データ収集

使う場面: 自分で運転して学習データを集める。起動すると、新しいセッションのフォルダ（data/raw/<日時>）を作ります。

  1. 上の帯の fps が 10 以上（緑）になっているのを確かめます。足りない時は Wi-Fi か Pi の負荷を見直します。
  2. 「前進の速さ」を決めます（40〜100、既定 50。40 より遅いと車輪が回りません）。
  3. ウィンドウを選んだ状態で R を押すか「● 録画を始める」で録画を始め、運転します。上の帯が「● 録画中」になります。
  4. 終わったら R で一時停止し、ウィンドウを閉じます。
キー / パッド操作
W / A・ZR前進（押している間）。パッドの B・ZL は後退
S / X停止
A D / 左スティック・十字←→舵を左 / 右へ（十字は舵いっぱい）
X / －舵を中央へ
Q E / L・R押している間、意図（行きたい向き）を左 / 右にする
R / ＋録画の開始・一時停止

運転のきまり: 基本はまっすぐ、塞がれたら空いている側へ曲がる。意図は「その先の分かれ道でどちらへ行きたいか」です。後退中のフレームは学習に使いません。指令と実際の動きが食い違うと（「動きの確認」が赤）、自動で止まります。走行の操作をすべて離してから押し直してください。

引数: なし。

データ確認・ラベル

使う場面: 集めたデータを見て、おかしいフレームを学習から外す、意図や前方の塞がりを直す、データの偏りを統計で見る。

  • フレームタブ: 「表示」と「条件」で絞り込みます。表の色は、緑=学習に使う、灰=使わない（止まっている等）、黄=注意あり、赤=手作業で除外、です。見出しの右クリックで、表示する列を選べます。
  • 表の下の帯は、セッション全体の流れ（状態の色と舵角の線）です。ドラッグした範囲のフレームを選べます。
  • 右側の「ラベル」で、選んだすべてのフレームに、タグ、学習からの除外、意図・前方の上書き、メモを付けます。
  • 統計タブ: 列ごとの数と割合、2つの列の組み合わせです。表の行をダブルクリックすると、その値で絞り込んでフレームへ戻ります。
キー操作
Space再生・停止
X選んだフレームの除外を切り替え
I / O範囲の始まり / 終わりを決める（Shift+クリックでも範囲を選べます）
Ctrl+Z元に戻す

ラベルは data/annotations/<セッション>.json に、変えるたびに保存します。元の走行データは書き換えません。学習は configs/train.toml の annotations = true でこのラベルを使います。

引数意味既定
--data_dir見るセッション、またはその親のフォルダ（複数可）data/raw data/interventions

ツールと引数

引数は、起動の画面の「実行引数」に、スペースで区切って書きます。-- で始まる名前の後ろに値を書きます（例: --epochs 20）。値のない引数（例: --verify）は、書くだけで有効になります。--turn_intent のような有り無しの設定は、--no-turn_intent で無効にできます。

データ

マニフェスト作成・検証 src.e2e.dataset.manifest

使う場面: 集めたセッションに封をする（作成）。学習の前や、データを動かした後に、変わっていないか確かめる（検証）。

引数意味既定
--data_dirセッション、またはその親のフォルダdata/raw
--verify付けると検証。付けないと、マニフェストのないセッションに作る（既にあるものは書き換えない）なし

例: 作成 --data_dir data/raw / 検証 --data_dir data/raw --verify

セッションの報告 src.e2e.dataset.session_report

使う場面: 集めた直後に、学習に使える走りになっているかを確かめる。fps が 10 未満、走っているフレームが少ない、左右の偏り、舵を切りすぎたフレーム、センサー値の欠けなどを「注意」として出します。

引数意味既定
--data_dirセッション、またはその親のフォルダdata/raw

例: 1セッションだけ --data_dir data/raw/20261113_000453

データのクリーニング src.e2e.dataset.cleaner

使う場面: モデルの予測と大きく食い違うフレーム（運転のミスなど）を自動で外したデータを、別のフォルダに作る。元のデータは変えません。手で選ぶ場合はデータ確認・ラベルを使います。

引数意味既定
--model 必須誤差を測るモデル（.onnx か .pth）—
--data_dir元のデータ（複数可）data/raw
--output_dirきれいにしたデータの置き場所data/processed/clean_v1
--threshold許す舵角の誤差（-1〜1 の尺度）。これより大きいフレームを外す0.4
--top_k_percent誤差の大きい順に、この割合（%）を外すなし

例: --data_dir data/raw --model models/v006/model.onnx --output_dir data/processed/clean_v2 --threshold 0.4

学習・評価

モデル学習 src.e2e.training.train

使う場面: 新しいモデルを作る。結果は models/<版>/ に、ONNX と、使ったデータ・コード・環境・設定の記録（metadata.json）として残ります。

引数意味既定
--data_dir 必須学習のデータ。親フォルダ（data/raw）、1セッション、または複数—
--output_dir 必須新しい版のフォルダ。既にある版は指定しない（Control Center は次の版を自動で入れます）—
--config設定のファイル。普段は configs/train.toml を指定し、変えたい値だけ下の引数で上書きしますなし（組み込みの値）
--epochs学習の回数設定の値（15）
--batch_size / --lr / --seed一度に学ぶ数 / 学習率 / 乱数の種32 / 0.001 / 42
--val_sessions検証に使うセッション ID（複数可）。指定しないと名前順で最後のセッションなし
--blocked_loss_weight「前方が塞がっているか」の出力を学ぶ重み。0 なら学ばない0
--turn_intent / --no-turn_intent曲がりの区間に、曲がった向きを意図として付け直す有効
--blocked_stuck / --no-blocked_stuck引っかかったフレームを「塞がっている」とする有効
--flip_augment / --no-flip_augment左右反転した複製を加える（学習の時間が倍）無効

例: いつもの学習 --config configs/train.toml --data_dir data/raw --output_dir models/v007
回数を増やす --config configs/train.toml --data_dir data/raw --output_dir models/v008 --epochs 25

学習の検証の値は、モデルの選択にも使った値なので少し甘く出ます。設定を変えた効果は交差検証で確かめます。

交差検証 src.e2e.training.cross_validate

使う場面: 設定を変えた効果を偏りなく測る。セッションを1つずつ抜いて学習し、抜いたセッションで評価します（セッション数だけ学習するので時間がかかります）。

引数意味既定
--data_dir 必須データ（学習と同じ書き方）—
--config設定のファイル（普段は configs/train.toml）なし
--output結果の JSON。何を変えたか分かる名前にします（例: data/cv/flip_on.json）。比較と来歴に使いますなし（画面に出すだけ）
--epochs / --seed学習の回数 / 乱数の種設定の値
--blocked_loss_weight、--turn_intent、--blocked_stuck、--flip_augment学習と同じ意味。試したい設定だけ変えます設定の値

例: 左右反転を試す --config configs/train.toml --data_dir data/raw --flip_augment --output data/cv/flip_on.json

交差検証の比較 src.e2e.evaluation.compare_cv

使う場面: 2つの交差検証の結果を比べ、候補を採用してよいか判定する。同じデータで同じセッションを抜いた結果どうしだけを比べます。

引数意味既定
--current 必須今使っている設定の結果（data/cv/*.json）—
--candidate 必須候補の設定の結果—
--tolerance全体の MAE がこれだけ悪くなっても「悪くない」とみなす幅0.0
--output判定を JSON で残す（比較・評価の画面に出ます）なし

判定: 採用してよい（adopt）/ 今の設定のまま（keep_current: 全体の MAE が悪くなった、または「意図ごとの平均」の基準に負けた）/ 比べられない（not_comparable: データや抜いたセッションが違う）。最後に採用するのは人です。

例: --current data/cv/auto_8sessions_turn.json --candidate data/cv/flip_on.json --output data/cv/compare_flip.json

オフライン評価 src.e2e.evaluation.evaluate

使う場面: あるモデルを、指定したデータ全部で評価し、eval_metrics.json を書く。学習に使ったデータを入れると、その分も含まれるので、走りの良さの比較には使いません。

引数意味既定
--data_dir 必須評価のデータ—
--model_path 必須モデルの重み（models/<版>/best_model.pth）—

モデル比較 src.e2e.registry.compare

使う場面: データとモデルの一覧を文字の表で出す（Control Center のモデル画面と同じ内容の簡易版）。

引数意味既定
--targetall、datasets、models のどれかall
--data_dir / --models_dirデータ / モデルのフォルダdata/raw / models

介入率の集計 src.e2e.evaluation.interventions

使う場面: 走行の記録から、モデル別の人と安全機能の介入の回数を表で出す（走行記録の画面と同じ内容）。

引数意味既定
--runs_dir走行の記録のフォルダdata/runs
--json表ではなく JSON で出すなし

配置

Pi へ接続するツールの準備: 接続先を、Control Center を起動する前に環境変数 PICARX_SSH_HOST（例: pi@rspi）で決めておくか、引数の先頭に --host pi@rspi を付けます。Control Center のジョブはパスワードを入力できないので、SSH の鍵で、パスワードなしで接続できるようにしておきます。

バンドル作成 src.e2e.deploy.bundle

使う場面: Pi へ送るフォルダを作って、Pi で読めるか（ファイルのハッシュ、入力の大きさ、使えない演算がないか）を先に確かめる。配置そのものは「Pi へ配置」が中でこれを行います。

引数意味既定

車体チェック

安全チェック src.e2e.m1_check

使う場面: 車体の状態や安全機能（指令の期限切れ、障害物、段差、Wi-Fi の切断で止まるか）を確かめる。最初の言葉で何をするかを選びます。

操作内容車体主な引数
status状態を表示—なし
cameraカメラの配信の fps を測る—--seconds 20
events安全イベントと、止まるまでの時間を表示—なし
ttl接続が切れた時に、指令の期限で止まるか少し動く--i-understand-the-car-will-move
approach障害物や段差に近づけて止まるか動く--speed 50 --seconds 3 --i-understand-the-car-will-move
wifi走行中に Wi-Fi が切れた時に止まるか動く--seconds 30 --speed …、PC の Wi-Fi を切らない時は --simulate --ssh_host <Pi>、--i-understand-the-car-will-move

例: status / camera --seconds 20 / approach --speed 50 --i-understand-the-car-will-move

動きの計測 src.e2e.m3_check

使う場面: 「指令と実際の動きの食い違い」の検出を、実機で計測して校正する。記録は data/m3_checks/ に残ります（画像は含みません）。

引数意味既定
run --scenario <場面>場面ごとに計測。still（止めたまま）、walk（前を人が横切る）、push（手で押す）、forward（直進）、left / right（舵を切って前進）、lifted（後輪を浮かせて前進の指令）—
--speed / --steer / --seconds速さ / 舵角（既定は場面ごと）/ 時間50 / 場面ごと / 5
--note床の種類や明るさなどのメモなし
--i-understand-the-car-will-moveforward、left、right、lifted では必須（車体が動く）—
calibrate --still … --moving …記録から設定（configs/motion.toml）の値を提案する。--push、--turn と --measured_deg、--straight、--wall も使えます—

例: run --scenario still / run --scenario forward --i-understand-the-car-will-move

速度チェック src.e2e.speed_check 車体が動く

使う場面: 床が変わった時などに、車輪が回り始める最低の速度を測る。壁の 1〜1.5m 手前に、壁へまっすぐ向けて置いてから起動します。

引数意味既定

--i-understand-the-car-will-move 必須車体が壁へ向かって動くことの了承—

使う場面: Pi で使用中のモデルで自律走行させる。推論と避ける判断は Pi で行い、PC は開始・見守り・停止をします。止める時は、ジョブの画面の「■ 車体を止めて終了」か緊急停止を使います。

--i-understand-the-car-will-move 必須車体が動くことの了承—

困った時

症状原因と対処
「サーバーに接続できません」「Failed to fetch」Control Center のサーバーが止まっています。起動し直して、ページを開き直します
「トークンが違います」サーバーを起動し直すと合言葉が変わります。ページを開き直します
右上が「Pi 未接続」Pi の電源、Wi-Fi、Pi の API サーバー（./picar-x-rust）を確かめます。車体を使わない作業（学習・評価・管理）はそのままできます
Pi への配置や取り込みのジョブが止まる・失敗するSSH のパスワードを聞かれていると、ジョブでは入力できません。鍵で接続できるようにするか、ターミナルで実行します
モデルが「要対応」になる学習の後にデータが変わったか、ONNX がありません。モデル詳細の「来歴の確認」で理由を見て、データを戻すか学習し直します
収集の fps が 10 未満Wi-Fi が弱いか、Pi の負荷が高いです。Pi の近くで収集するか、ほかの処理を止めます
Qt の画面の文字が重なる・はみ出すウィンドウを広げるか、列の境目を動かします。右の列は足りない時にスクロールします
